# App Hub 要求・要件定義書

## 1. プロジェクト概要

### 1.1 プロジェクト名

App Hub

### 1.2 背景

バイブコーディングによって、個人で利用する小規模なWebアプリやPWAが増えてきている。

現在は、それぞれのアプリURLがVercel、GitHub、Notion、Google Drive、ブックマーク、チャット履歴などに散らばっており、必要なアプリにすぐアクセスしづらい状態になっている。

そのため、個人で使うアプリリンクを一元管理できるポータルページを作成する。

### 1.3 目的

個人で使うWebアプリやPWAへのリンクを、1つのページに集約する。

このポータルを開けば、必要なアプリをすぐに見つけてアクセスできる状態を作る。

### 1.4 ゴール

- 個人用アプリリンクを一覧表示できる
- アプリリンクの追加、編集、削除ができる
- スマホ、タブレット、PCで見やすく使える
- 見た目が美しく、使うたびに気分が上がる
- Vercelにデプロイできる
- Neonをデータベースとして利用できる

### 1.5 非ゴール

初期開発では、以下は対象外とする。

- チーム利用
- 複雑な権限管理
- アプリごとの利用ログ分析
- 外部API連携
- 各アプリの死活監視
- 高度な検索エンジン
- SSO連携
- 複数ユーザー対応

ただし、将来的に拡張できる設計にはしておく。

## 2. 想定ユーザー

### 2.1 メインユーザー

個人利用者。

自分で作成したアプリ、よく使う外部サービス、PWA化したツールなどをまとめて管理したい人。

### 2.2 利用シーン

- 作業開始時にポータルを開く
- 作ったアプリのURLを忘れたときに探す
- スマホからよく使うアプリへアクセスする
- 新しく作ったアプリを登録する
- 使わなくなったアプリを削除する
- アプリ名やURLが変わったときに編集する

## 3. 全体コンセプト

### 3.1 プロダクトコンセプト

自分だけの水中宮殿のようなアプリランチャー。

単なるリンク集ではあるが、見た目は雑にしない。

アプリを開くたびに、静かで深く、高級感のある水中空間に入るような体験を目指す。

### 3.2 デザインコンセプト

テーマ：

水中 × ゴージャス × 静けさ × 透明感

キーワード：

- Deep Ocean
- Luxury
- Aqua Glass
- Blue Light
- Pearl
- Crystal
- Flow
- Calm
- Premium
- Personal Command Center

### 3.3 デザインの方向性

- 背景は深海のような濃いブルー系
- 光が水中で揺らぐようなグラデーション
- カードはガラスのような半透明デザイン
- アクセントにゴールド、シアン、パールホワイトを使用
- 高級ホテルのラウンジや水中宮殿のような雰囲気
- 操作性を犠牲にしない
- 文字は読みやすく、ボタンは押しやすくする

## 5. 機能要件

### 5.1 アプリリンク一覧表示

登録されているアプリリンクをカード形式で一覧表示する。

各アプリカードには以下を表示する。

- アプリ名
- 説明文
- URL
- カテゴリ
- ステータス
- アイコンまたは絵文字
- 最終更新日
- 開くボタン
- 編集ボタン
- 削除ボタン

表示ルール：

- 新しい登録順、または任意の並び順で表示する
- 初期実装では新しい登録順でよい
- カード全体をクリックしてアプリに遷移できる
- 外部リンクは新しいタブで開く
- スマホでは1列表示
- タブレットでは2列表示
- PCでは3列以上のグリッド表示

### 5.2 アプリリンク追加

必須項目：

- アプリ名
- URL

任意項目：

- 説明文
- カテゴリ
- ステータス
- アイコンまたは絵文字
- 表示順
- メモ

バリデーション：

- アプリ名は1文字以上
- URLは正しいURL形式
- URLはhttpまたはhttpsで始まる
- 同じURLの重複登録は初期段階では許可してもよい
- 将来的には重複警告を出せるとよい

登録後の挙動：

- 登録成功後、一覧に反映される
- 入力フォームは閉じる
- 成功メッセージを表示する

### 5.3 アプリリンク編集

登録済みのアプリリンク情報を編集できる。

編集可能項目：

- アプリ名
- URL
- 説明文
- カテゴリ
- ステータス
- アイコンまたは絵文字
- 表示順
- メモ

編集後の挙動：

- 保存後、一覧表示に即時反映される
- 成功メッセージを表示する
- キャンセルした場合は変更しない

### 5.4 アプリリンク削除

不要になったアプリリンクを削除できる。

削除ルール：

- 削除ボタンを押すと確認ダイアログを表示する
- 確認後に削除する
- 誤操作防止のため、ワンクリック削除は禁止する

削除後の挙動：

- 一覧から該当カードを削除する
- 成功メッセージを表示する

### 5.5 カテゴリ管理

初期実装では、カテゴリはアプリリンク登録時にテキストで入力する。

カテゴリ専用の管理画面は初期実装では不要。

想定カテゴリ例：

- Work
- AI
- Development
- Sports
- Handball
- Finance
- Documents
- Personal
- Prototype
- Archive

将来的な拡張：

- カテゴリ一覧管理
- カテゴリごとの色設定
- カテゴリ別フィルタ
- カテゴリ並び替え

### 5.6 ステータス管理

各アプリの状態を分かるようにする。

初期ステータス：

- active
- testing
- idea
- archived

表示名：

- active：稼働中
- testing：テスト中
- idea：構想中
- archived：保管

表示ルール：

- activeは目立つ表示にする
- archivedはやや暗く表示する
- testingは試作感が分かる表示にする
- ideaは軽めの表示にする

### 5.7 検索機能

初期実装では可能であれば実装する。

検索対象：

- アプリ名
- 説明文
- URL
- カテゴリ
- メモ

挙動：

- 入力に応じてリアルタイムに絞り込む
- 大文字小文字は区別しない
- 空欄の場合は全件表示

### 5.8 フィルタ機能

初期実装では必須ではない。

将来的に欲しいフィルタ：

- カテゴリ別
- ステータス別
- PWA対応有無
- よく使うもの
- アーカイブ除外

### 5.9 お気に入り機能

初期実装では必須ではない。

将来的な仕様：

- アプリをお気に入り登録できる
- お気に入りは上部に表示する
- 星アイコンで切り替える

### 5.10 PWA対応

このポータル自体をPWA化する。

対応内容：

- manifestを設定する
- アプリアイコンを設定する
- スマホのホーム画面に追加できるようにする
- displayはstandaloneを想定する
- start_urlはトップページにする

注意点：

ポータルをPWA化しても、リンク先アプリまで自動的にPWAとして開くわけではない。各アプリがPWA挙動をするかどうかは、各アプリ側の設定とブラウザ、OSの挙動に依存する。

## 7. データ要件

### 7.1 app_links テーブル

アプリリンク情報を保存する。

項目：

- id: uuid、主キー、自動生成
- name: text、必須、アプリ名
- url: text、必須、アプリURL
- description: text、任意、アプリ説明
- category: text、任意、カテゴリ名
- status: text、必須、初期値 active
- icon: text、任意、絵文字またはアイコン文字列
- memo: text、任意、個人用メモ
- sort_order: integer、任意、表示順
- created_at: timestamp、必須、作成日時
- updated_at: timestamp、必須、更新日時

statusの値：

- active
- testing
- idea
- archived

### 7.2 Prismaモデル

```prisma
model AppLink {
  id          String   @id @default(uuid())
  name        String
  url         String
  description String?
  category    String?
  status      String   @default("active")
  icon        String?
  memo        String?
  sortOrder   Int?
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt

  @@map("app_links")
}
```

## 8. API要件

### 8.1 一覧取得

- エンドポイント: `GET /api/app-links`
- 登録されているアプリリンクを取得する
- レスポンスは `appLinks` の配列
- `sort_order` がある場合は `sort_order` 順、未指定は `created_at` 降順

### 8.2 新規作成

- エンドポイント: `POST /api/app-links`
- 新しいアプリリンクを作成する
- 必須パラメータ: `name`, `url`
- 任意パラメータ: `description`, `category`, `status`, `icon`, `memo`, `sort_order`

### 8.3 更新

- エンドポイント: `PATCH /api/app-links/:id`
- 指定したアプリリンクを更新する

### 8.4 削除

- エンドポイント: `DELETE /api/app-links/:id`
- 指定したアプリリンクを削除する

## 11. セキュリティ要件

### 11.1 初期認証方針

MVPでは簡易パスワード認証を実装する。

- 環境変数に管理用パスワードを設定する
- 初回アクセス時にパスワード入力を求める
- Cookieでログイン状態を保持する

### 11.2 環境変数

必要な環境変数：

- `DATABASE_URL`: Neon PostgreSQL接続URL
- `APP_PASSWORD`: 簡易認証用パスワード

### 11.3 注意事項

- DATABASE_URLをGitHubにコミットしない
- .envファイルをコミットしない
- 削除APIは確認UIを通して呼び出す
- SQLインジェクションを避けるため、ORMを使用する

## 12. パフォーマンス要件

### 12.1 初期表示

- 登録アプリ数が100件程度でも快適に表示できる
- 初期表示はなるべく軽くする
- 不要な画像を大量に読み込まない

### 12.2 操作感

- 追加、編集、削除後の反映が速い
- ローディング状態を表示する
- 保存中にボタンを連打できないようにする

## 13. エラーハンドリング要件

### 13.1 入力エラー

- アプリ名が空の場合、エラー表示
- URL形式が不正な場合、エラー表示

### 13.2 通信エラー

- データ取得に失敗した場合、再読み込みを促す
- 保存に失敗した場合、再試行を促す
- 削除に失敗した場合、削除されていないことを明示する

### 13.3 空状態

- 登録データがない場合、空状態UIを表示する
- エラーではなく、自然な初期状態として扱う

- アプリ名とURLを入力して新規登録できる

- 登録済みアプリの情報を編集できる

- 削除前に確認ダイアログが表示される

### 16.5 レスポンシブ

- スマホで横スクロールが発生しない

- 高級感がある

### 16.7 デプロイ

- 本番環境で追加、編集、削除ができる

5. アプリリンク一覧取得機能を作る
6. 追加、編集、削除機能を作る
7. 水中ゴージャス系のUIを作り込む
8. レスポンシブ対応を確認する
9. PWA対応を行う
10. Vercelにデプロイして本番確認する

## 19. 開発時の注意

- まずは機能をシンプルに作る
- デザインは後からでも磨けるが、今回は見た目も重要なので最低限の美しさは最初から担保する
- 水中風デザインに寄せすぎて可読性を落とさない
- カードのクリック領域を広くする
- スマホでの操作性を必ず確認する
- DB接続情報を絶対に公開しない
- 削除確認は必ず入れる
- 個人用なので、過剰に複雑化しない

## 20. 最終的に作りたい体験

朝、作業を始めるときにこのポータルを開く。

深い青の水中空間のような画面に、自分が作ったアプリやよく使うサービスが美しく並んでいる。

必要なツールを迷わず開ける。

新しく作ったアプリもすぐに登録できる。

使わなくなったものは整理できる。

ただのリンク集だが、自分の作業環境の入口として気持ちよく使える。

このプロダクトは、個人のための小さなコックピットである。
